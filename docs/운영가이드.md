# asset-sync 운영 가이드

hosts 파일 또는 자산 엑셀을 시작점으로 IT 자산을 **읽기 전용으로 수집 → 검증 → NetBox에 멱등 등록**하는 방법을 자세히 설명합니다. 데모 실행 방법은 [README](../README.md)를 보세요.

```
hosts 파일 ─▶ parse ─▶ hosts_normalized.csv/json + Ansible inventory + parse report
                         │  (OS/Site/Role/BMC는 host_overrides.yml로 지정, 스캔 없음)
                         ▼
     collect_linux.yml (SSH facts) / collect_windows.yml (WinRM CIM) / assetctl bmc (Redfish GET, ipmitool)
                         │  실패 → data/raw/<os>/<host>.status.json (사유 기록 후 건너뜀)
                         ▼
     build ─▶ data/assets.json  (필드마다 value / source / collected_at / confidence)
                         ▼
     sync (기본 dry-run) ─▶ sync_plan_*.md/json, review_report.csv
                         ▼  사용자 승인
     sync --apply (max_hosts 가드, 확인 프롬프트) ─▶ NetBox REST API
                         ▼
     NetBox dynamic inventory (inventory/netbox.yml), systemd timer, 읽기 전용 MCP
```

## 디렉터리

| 경로 | 내용 |
|---|---|
| `scripts/assetctl.py` | CLI: `parse`, `bmc`, `build`, `check`, `sync`, `report` |
| `scripts/asset_sync/` | 파서, 정규화, BMC 수집기, NetBox 클라이언트, 동기화 엔진 |
| `scripts/deploy_netbox.sh` | 공식 netbox-docker 배포 (기본 dry-run, `--apply`로 실행) |
| `scripts/backup_netbox.sh` | pg_dump + media + env 백업, 보관 기간 적용 |
| `scripts/setup_mcp.sh` | netboxlabs/netbox-mcp-server 설치 및 `.mcp.json` 생성 |
| `scripts/run_pipeline.sh` | 전체 파이프라인 실행 |
| `playbooks/` | 수집 플레이북, `netbox_bootstrap.yml`(Site/Role/Cluster/커스텀 필드/태그) |
| `inventory/` | `host_overrides.yml`, `netbox.yml`(dynamic inventory), `group_vars/`, `hosts.generated.yml`(parse/import-excel이 생성, Git 제외) |
| `config/settings.yml` | 기본값, 분류 목록, 제외 NIC, 제조사 별칭, 동기화 정책 |
| `deploy/systemd/` | 주기 동기화/백업 타이머 |
| `reports/`, `data/` | 산출물. **Git 제외**(시리얼·MAC 포함), 파일 권한 0600 |
| `tests/` | 픽스처 + 인메모리 Fake NetBox 기반 테스트 |

## NetBox

- **기존 NetBox가 있으면** `.env`에 `NETBOX_URL`과 토큰을 넣고 `assetctl.py check`부터 실행합니다. 재구축하지 않습니다.
- **없으면** `scripts/deploy_netbox.sh`(dry-run)로 계획을 확인한 뒤 `--apply`로 배포합니다.
  - netbox-docker `5.1.1`(NetBox v4.7)에 고정합니다. 업스트림 env 파일의 예시 시크릿(SECRET_KEY, DB/Redis 비밀번호, API_TOKEN_PEPPER)은 첫 배포 때 재생성합니다.
  - 영속 볼륨: `netbox-postgres`, `netbox-media-files`, `netbox-redis-data`, `netbox-reports-files`, `netbox-scripts-files`
  - 공개 주소는 `https://<NETBOX_PUBLIC_IP>`입니다. nginx 프록시가 TLS를 처리하고 80번 요청은 443으로 리다이렉트합니다. `127.0.0.1:8000`은 로컬 확인용 평문 포트입니다.
  - 인증서는 자체 서명(`/opt/netbox-docker/proxy/certs/netbox.crt`)입니다. 사내 인증서로 같은 파일명에 교체한 뒤 `docker compose restart proxy`를 실행하면 됩니다.
  - 튜닝값: Granian 워커 8, PostgreSQL `shared_buffers=2GB`, `effective_cache_size=6GB`(`.env`에서 조정). 첫 기동 때 마이그레이션에 약 4분 걸립니다.
  - `LOGIN_REQUIRED=True`이므로 토큰 없이 API를 호출하면 403이 돌아옵니다. 정상 동작이며, 버전은 응답 헤더 `API-Version`으로 확인할 수 있습니다.
  - 백업: `deploy/systemd/netbox-backup.timer` → `scripts/backup_netbox.sh`
- 토큰은 두 개로 나눕니다. `NETBOX_TOKEN`은 읽기 전용(MCP, dry-run, dynamic inventory), `NETBOX_WRITE_TOKEN`은 `--apply`와 bootstrap 전용입니다.

```bash
.venv/bin/ansible-playbook playbooks/netbox_bootstrap.yml                 # check mode
.venv/bin/ansible-playbook playbooks/netbox_bootstrap.yml -e apply=true   # 승인 후
```
bootstrap은 태그 `asset-sync`, 커스텀 필드 `mgmt_nic`(인터페이스/VM 인터페이스, boolean)와 `bmc_ip`(디바이스), 그리고 `config/settings.yml`의 `classification`에 적힌 Site/Role/Cluster Type/Cluster를 만듭니다.

## MCP (읽기 전용)

```bash
scripts/setup_mcp.sh                 # tools/netbox-mcp-server (v1.2.2) + .mcp.json
set -a; . ./.env; set +a; claude     # /mcp 에서 netbox 연결 확인
```
`.mcp.json`은 `${NETBOX_URL}`, `${NETBOX_TOKEN}`을 참조하므로 토큰이 파일에 남지 않습니다. 공식 MCP는 읽기 전용이며, 쓰기는 이 프로젝트의 sync/bootstrap으로만 합니다.

## hosts 파싱 검사 항목

`assetctl.py parse`는 다음을 검사해 `reports/hosts_parse_report.md`에 기록합니다.

| 검사 | 처리 |
|---|---|
| 잘못된 IP, 이름 없는 행, 잘못된 hostname, 비ASCII | `invalid` |
| loopback, link-local, multicast, unspecified | `excluded` |
| 한 IP에 서로 다른 호스트 / 한 이름에 여러 IPv4 | `review`. 인벤토리의 `skipped` 그룹으로 보내 수집하지 않음 |
| alias 충돌, hosts 파일 안의 CIDR, IPv6 zone id | `review` |
| IPv6 / dual-stack | 지원(정보로 표시) |
| 마스크 | hosts 파일에는 마스크가 없음. 수집된 prefix를 우선 사용하고, `config/subnets`에 없으면 `mask_unknown`으로 표시 |
| `*-bmc`, `*-idrac` 등의 이름 | 기본 호스트의 BMC 후보로 연결(medium 신뢰도. Redfish로 확인되면 high) |

## 자산 엑셀 입력 (hosts 파일 대신 사용 가능)

```bash
.venv/bin/python scripts/assetctl.py import-excel --file "demo/data/demo_assets.xlsx"            # IDC별 시트 (excel.sheets)
.venv/bin/python scripts/assetctl.py import-excel --file ledger.xlsx --sheet "장비 목록" --site pangyo  # 시트 하나만
# 또는 .env에 ASSET_SYNC_EXCEL_FILE (/ ASSET_SYNC_EXCEL_SITE)를 설정한 뒤 scripts/run_pipeline.sh 실행
```
- 설정은 `config/settings.yml`의 `excel:` 항목에서 합니다. 포함할 카테고리(A열), 모델명으로 Role을 정하는 규칙(`role_rules`)을 지정합니다.
- **IDC별 시트**: `excel.sheets`에 시트 이름마다 Site와 `cluster_map`(VM 플랫폼 → Cluster)을 적으면 모든 시트를 한 번에 가져옵니다.
  출처는 `excel:판교 IDC!row45`처럼 시트 이름까지 남고, 시트가 달라도 같은 hostname이면 둘 다 `duplicate_hostname`으로 보류합니다.
  `--site` 또는 `--sheet`를 주면 `excel.sheets`를 무시하고 그 시트 하나만 읽습니다.
- 장비 하나는 모델명 열의 병합 셀 하나로 판단하고, 병합된 행 수를 U 높이로 씁니다. `R01-42`는 랙 R01로 해석하며, NetBox 위치는 장비가 차지하는 가장 낮은 U로 계산합니다.
- **읽지 않는 열**: `ID / PW`, `password`, `account`, `비고`, `담당자`, `사용 기간`, `e-mail`, `연락처`
- **엑셀 값의 쓰임**
  - 분류 정보(Site, Role, Rack, Cluster): 그대로 사용합니다.
  - 사실 정보(S/N, 모델, MGMT IP, MAC): 수집값과 대조할 때만 씁니다. 값이 같으면 출처에 `+excel`을 붙이고, 다르면 수집값을 적용한 뒤 review로 보냅니다. 수집값이 없으면 medium 신뢰도로 review에 올립니다.
  - **S/N이나 물리/가상 구분이 엑셀과 다르면** 그 엑셀 행이 다른 장비를 가리키는 것일 수 있습니다. 이 경우 랙 배치를 적용하지 않습니다.
- 엑셀 hostname 칸에 설명이 들어 있어 이름으로 쓸 수 없으면 `ip-<OS IP>` 키로 수집합니다. NetBox 장비 이름은 서버에서 수집한 hostname을 씁니다.
- 랙 U 위치(position)는 엑셀 시리얼이 수집 시리얼과 같고, NetBox 위치가 비어 있고, Device Type 높이가 엑셀 병합 셀 높이와 같고,
  그 U 범위를 다른 장비가 쓰지 않을 때만 반영합니다(면은 `front`). 하나라도 어긋나면 위치만 review로 보내고, 이미 있는 위치는 옮기지 않습니다.

## 신뢰도와 반영 규칙

- **high**: 인증된 직접 조회 결과(SSH facts, CIM, Redfish)이면서 placeholder가 아닌 값. 이 값만 자동 반영합니다.
- **medium**: 휴리스틱으로 얻은 값(이름 패턴으로 찾은 BMC, 기본 경로로 추정한 관리 NIC). review로 보냅니다.
- **conflict**: 출처끼리 값이 다른 경우(예: OS 시리얼과 BMC 시리얼 불일치). review로 보내고, 식별 필드이면 해당 자산 전체를 보류합니다.

동기화(`sync.py`)는 다음 순서로 동작합니다.
1. **게이트 검사**: 수집에 성공했는지, hostname이 hosts 파일과 일치하는지, 물리/가상이 판별됐는지, Site·Role(VM은 Cluster)이 지정돼 있는지 확인합니다. 하나라도 통과하지 못하면 skipped 또는 review가 됩니다.
2. **식별자 검증**: serial로 찾은 객체와 이름으로 찾은 객체가 같은지, 중복이 없는지 확인합니다. Device와 VM 사이의 종류 충돌, asset tag 중복도 검사합니다.
3. **신규 생성 또는 빈 값 채우기**: 값이 다른 필드는 덮어쓰지 않고 `review_report.csv`로 보냅니다.
4. **하위 객체 처리**: 인터페이스는 실제 이름 그대로 등록하고 `mgmt_nic`을 표시합니다. MAC은 NetBox 4.2 이상이면 MACAddress 객체로, 미만이면 `mac_address` 필드에 넣습니다. IP는 다른 객체에 할당돼 있으면 옮기지 않습니다. primary IP는 접속에 사용한 IP일 때만 설정합니다.
5. **이력**: 생성하거나 변경할 때마다 저널에 출처와 수집 시각을 남깁니다. 시리얼 값 자체는 기록하지 않습니다.
6. **삭제 없음**: 삭제 기능은 구현돼 있지 않습니다. `asset-sync` 태그가 있지만 이번 수집에 나타나지 않은 객체는 보고만 합니다.

관리 NIC 판정 기준은 **Ansible이 접속한 IP를 가진 NIC**입니다. NetBox의 `mgmt_only`는 전용 OOB 포트라는 뜻이라 일반 NIC에 쓰지 않고, 커스텀 필드 `mgmt_nic`로 따로 표시합니다.

## 파일럿(5대) → 확장

```bash
printf "web01\nweb02\napp01\nwin01\ndb01\n" > inventory/pilot.txt
scripts/run_pipeline.sh --limit pilot           # 수집 + dry-run 계획 + 보고
# reports/sync_plan_*.md, reports/review_report.csv, reports/run_report.csv 검토
scripts/run_pipeline.sh --limit pilot --apply   # 승인 후 실제 반영 (확인 프롬프트)
scripts/run_pipeline.sh --limit pilot           # 두 번째 실행 → 변경 0 확인(멱등성)
```
`report`는 자산을 success / failed / unverified / duplicate로 집계합니다. 대상을 넓힐 때는 `--max-hosts N`(또는 `ASSET_SYNC_MAX_HOSTS`)을 명시적으로 올려야 합니다.

## Dynamic Inventory / 주기 동기화

```bash
NETBOX_API=$NETBOX_URL .venv/bin/ansible-inventory -i inventory/netbox.yml --graph
cp deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/ && systemctl daemon-reload
systemctl enable --now asset-sync.timer netbox-backup.timer
```
타이머는 기본적으로 **dry-run만** 실행하고 보고서를 남깁니다. `.env`에 `ASSET_SYNC_AUTO_APPLY=true`를 설정했을 때만 high 신뢰도이면서 충돌이 없는 변경을 반영하며, 이때도 `max_hosts`를 넘지 못합니다.
v2 토큰(`nbt_...`)을 쓸 때는 `inventory/netbox.yml`에 `token: {type: Bearer, value: ...}`를 지정해야 합니다.

## 보안

- 비밀은 `.env`(0600, gitignore) 또는 Ansible Vault에만 둡니다. 수집 태스크는 `no_log`로 실행합니다. 로그 포매터는 token/password 패턴을 가립니다.
- 리포트 CSV에서 시리얼과 asset tag는 마스킹합니다(`AB***34`). 원본 값은 `data/assets.json`(0600, gitignore)에만 있습니다.
- Redfish는 GET과 Basic 인증만 사용합니다(세션 POST 없음). ipmitool 비밀번호는 `-E`로 환경 변수에서 넘겨 argv에 노출되지 않게 합니다. TLS 검증은 기본으로 켜져 있고 CA 번들을 지정할 수 있습니다.
